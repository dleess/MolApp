## Codebase Patterns
- The iPadOS app builds through `MolApp.xcodeproj` with shared scheme `MolApp`; use the README `xcodebuild` command with `CODE_SIGNING_ALLOWED=NO` for simulator verification.
- Keep `MoleculeViewerView` viewport-first: the primary viewer should be the back layer in a full-screen `ZStack`, with controls added as overlays instead of sidebars that resize the viewport.
- Bundled WKWebView assets should be added to the Xcode target resources and loaded with `loadFileURL(_:allowingReadAccessTo:)`; Xcode copies `MolApp/Resources/viewer.html` into the app bundle root as `viewer.html`.
- Mol* assets are copied as a `MolApp/Resources/molstar` folder resource, so `viewer.html` should load them with bundle-root-relative paths like `molstar/molstar.js` and `molstar/molstar.css`.
- `MolAppTests` is an XCTest target wired into the shared `MolApp` scheme; use `xcodebuild ... test CODE_SIGNING_ALLOWED=NO` for test verification when app code has test coverage.
- Local file import extension allowlists and Mol* data format mapping live in `LocalStructureFileLoader`; UI code should call that helper rather than duplicating `pdb`/`mmcif` handling.
- PDB ID loading should validate with `PdbIdentifier.normalized(...)` in native UI and route through `loadPdbId`; the viewer-side handler loads `https://files.rcsb.org/download/{PDB_ID}.cif` as `mmcif`.
- Keep iPad camera gestures owned by Mol*/`viewer.html`: disable WKWebView scroll and pinch interception, keep `#molstar-host` at `touch-action: none`, and add custom gesture behavior only when Mol* does not already provide it.
- Native viewport controls belong in `MoleculeViewerView` overlays and should call `MolStarBridge` commands directly; representation choices use `MoleculeRepresentation` raw values routed through `setRepresentation`.
- Structural visibility feature keys belong in `MoleculeVisibilityFeature` and should be routed through `MolStarBridge.toggleVisibility` from native overlay controls.
- Selection details flow through `MolStarBridge.currentSelection` using viewer-side `selectionChanged` messages; Mol* click loci can be converted with `StructureElement.Loci.getFirstLocation` and `StructureProperties`.
- Selection highlight and context dimming are viewer-side Mol* interactivity concerns: use `lociSelects.selectOnly` plus `lociHighlights.highlightOnly`, and clear both on `clearSelection` or before loading another structure.
